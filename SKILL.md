# Testing Lakeflow Jobs with pytest-databricks-lakeflow

The plugin deploys a bundle target once per session, then gives each test a throwaway copy of a job or of one task, runs it with chosen parameters, and deletes it. Full docs: https://stevenayers.github.io/pytest-databricks-lakeflow/ (machine-readable index: https://stevenayers.github.io/pytest-databricks-lakeflow/llms.txt).

## Before writing a test

1. Read the job in the bundle (`resources/*.yml` or wherever `include:` points). Note the resource key, the task keys, the declared `parameters`, and which tasks set or read task values.
2. Check `databricks.yml` has the target the tests use (default `test`). Recommend `mode: development` and a separate `workspace.root_path`. If several branches or people share the workspace, recommend the per-branch recipe from the docs ("Isolating test deployments"): a `lakeflow_suffix` variable in `root_path`, `experimental.skip_artifact_cleanup: true`, the sanitised branch name passed as `Lakeflow(variables={"lakeflow_suffix": ...})` from the `lakeflow` fixture in `conftest.py`, and `pytest --lakeflow-destroy` at the end of the pipeline.
3. Check the job code reads catalog and schema from job parameters, not bundle variables. If it does not, say so; per-test schemas cannot work otherwise.
4. Look for an existing `lakeflow` fixture override in `conftest.py`. Reuse it. Create one only if configuration is needed (another target, a `catalog`, a `profile`, a longer `timeout`).

## The API, and nothing else

Import from `pytest_databricks_lakeflow`: `Lakeflow`, `EphemeralJob`, `EphemeralPipeline`, `JobRun`, `TaskRun`, `TaskValues`, `TaskError`, `Timing`, `NotebookView`, `NotebookCell`, `RunHandle`, `SqlResult`, `PipelineUpdate`, `DebugNotebook`, `Stub`, `LakeflowError`, `LakeflowBundleError`, `LakeflowTimeout`, `LakeflowRunFailed`.

- `lakeflow` fixture (session scope) returns a `Lakeflow`. Override it to configure; all `Lakeflow` arguments are keyword-only: `bundle_root`, `target`, `profile`, `workspace_client`, `sync`, `variables`, `deploy_flags`, `timeout`, `poll_interval`, `catalog`, `helpers_path`, `helpers_compute`, `helpers_environment_version`, `disable_auto_optimization`, `performance_optimized`, `side_effects`, `environment_version`, `budget_policy_id`, `existing_cluster_id`, `single_node`, `allow_undeclared_params`, `test_marker`, `notebook_export`, `sweep_hours`, `keep`, `keep_failed`, `strict_artifacts`, `permissions`, `modify_settings`, `run_finished`. `strict_artifacts=True` raises `LakeflowError` on the first template lookup when the bundle has a wheel artifact (`type: whl`, or a `build` command and no `type`) without `dynamic_version: true`; by default that is one `UserWarning` per session ("Artifacts [...] have no dynamic_version: true. ..."), because serverless is reported to cache wheels by file name (databricks/cli#1621, #2958). With `sync="none"`, a local wheel of a bundle job built more than 60 seconds after its uploaded copy's `modified_at` gives one more `UserWarning` per session ("dist/pkg-0.1-py3-none-any.whl was built after its uploaded copy. Run `databricks bundle deploy -t <target>`."), which `strict_artifacts=True` also turns into `LakeflowError`. `timeout` also sets each job's `timeout_seconds` to the timeout plus 60 seconds, unless the template is stricter; `run(timeout=...)` or `start(timeout=...)` longer than that first lengthens the job's `timeout_seconds` to it plus 60 seconds with `jobs.update` (once per value, a warning when the template or `modify_settings` set the shorter one), while `RunHandle.wait(timeout=...)` longer than it raises `LakeflowError` because the run has started. `poll_interval` is the `timedelta` between two `get_run` polls of a running run (default two seconds; zero or less raises `ValueError`). `permissions` is a list of `jobs.JobAccessControlRequest` or dicts such as `{"group_name": "data-eng", "permission_level": "CAN_VIEW"}`, applied as the `access_control_list` of every ephemeral job; `IS_OWNER` raises `ValueError` (the creator owns every copy; use `CAN_MANAGE`). With `sync="deploy"`, setup runs `bundle validate` before `bundle deploy` and raises `LakeflowBundleError` when the target's or a job's `run_as` is another user, or a service principal on which the deploying identity has no Service Principal User role ("Target 'test' sets run_as <principal>, but this session deploys as <you>..."); fix it with `run_as: {user_name: ${workspace.current_user.userName}}` or deploy yourself and use `sync="none"`. `deploy_flags` is a list of extra `bundle deploy` flags such as `["--fail-on-active-runs"]` (used only with `sync="deploy"`; not `-t`, `--target`, `-e`, `--environment`, `-p`, `--profile`, `--var` or `--auto-approve`, which raise `ValueError`). `side_effects` is `"neutralise"` (default: pause dashboard and SQL alert subscriptions in the copy) or `"keep"`; alert tasks and Power BI tasks are left as they are in both, so disable them with `disable=`. The plugin needs databricks-sdk 0.100 or later, the first release whose `JobSettings` keeps `alert_task`. `notebook_export` is `"failed"` (default: export the notebook of each notebook task that ran and did not succeed into `TaskRun.notebook`), `"always"` (every notebook task that ran) or `"never"`; anything else raises `ValueError`. `test_marker=True` declares a `__pytest_test_id` job parameter on every copy with the test node id as its default (also when `name=` is passed), so job code can read it with `dbutils.widgets.get("__pytest_test_id")` or `{{job.parameters.__pytest_test_id}}`; it is off by default and is never in `run_now` parameters. `variables` is a mapping of bundle variable names to values, passed as `--var name=value` to every `bundle` command including `destroy`; instances with different `variables` deploy separately. Setup raises `LakeflowError` when the bundle target's `workspace.host` differs from the workspace client's host, read from `bundle validate` before the `run_as` check and before `bundle deploy` (and from `bundle summary` after the deploy). The plugin does not read the target from the environment: use `target=os.environ.get("LAKEFLOW_TARGET", "test")`.
- `lakeflow.job(key, params=None, capture_task_values=None, name=None, run_as=None, disable=None, *, task_params=None, force_conditions=None, children="warn", setup=None, teardown=None, teardown_at="run", extra_dependencies=None, environments=None, task_overrides=None, upstream_task_values=None, pipelines="deployed", schema=None, for_each_inputs=None, trigger=None) -> EphemeralJob`. `pipelines="copy"` with `schema=` (the full `catalog.schema` name `lakeflow.schema()` yields) copies each pipeline an enabled pipeline task updates (nested `for_each_task` tasks included, each pipeline once) as `lakeflow.pipeline()` does, named `[pytest] <name or node id> <pipeline bundle key>`, creates the copies just before the job (after `modify_settings`, which still sees the deployed ids, and choosing the pipelines again then, so a pipeline task `modify_settings` repoints or adds is copied too), points every pipeline task at its copy, and closes them just after the job with the same keep rules, except that when the job is not created (`jobs/create` refused it) they are deleted even with `keep_failed`; the copies are in `job.pipelines`; a copy has none of the deployed pipeline's `parameters`, which `pipelines/get` does not return, and on databricks-sdk 0.100 to 0.109 a deleted copy keeps its tables until its schema is dropped. `"copy"` without `schema`, `schema` without `"copy"`, or a job with no enabled pipeline task raises `LakeflowError`, and any other value of `pipelines` `ValueError`, before anything is created; the default `"deployed"` keeps every pipeline task on the deployed pipeline, so a run updates the deployed pipeline's tables. `upstream_task_values` is `{task_key: {value_key: value}}` or `{task_key: Stub(...)}` as for `task()`, whose `outputs` replace `{{tasks.<key>.output.<path>}}` references in every task of the copy: each named task of the copy becomes a stub with the same key and place that sets those task values, so downstream `depends_on`, `{{tasks.<key>.values.<name>}}` and `taskValues.get` resolve against it; it drops the task's `depends_on`, `run(only=...)` adds it when a selected task depends on it (a stub that no selected task depends on does not run, so a selected task reading its values raises `LakeflowError`; name the stub in `only`), and it appears in `run.injected_tasks`, not `run.tasks`; what `task_params`, `disable`, `force_conditions`, `extra_dependencies` and `task_overrides` set on that task is lost; an unknown key raises `LakeflowError`. `setup` and `teardown` each take one of three forms. A plain `def` function taking any of `spark`, `dbutils`, `params` (every job parameter of the run, as strings: declared ones, those passed under `allow_undeclared_params=True` to `job()` or `run()`, and those `modify_settings` declares). A list of SQL statements, each rendered with `string.Template` from the job parameters (`${schema}`, `$$` for a literal `$`) and run in order through `spark.sql`; `run.setup.output_json == {"statements": <count>}`; a `${name}` that the job does not declare and `params` of `job()` does not hold, an invalid `$`, a bare string, an empty list, or a set or generator of statements raises `LakeflowError` before anything is created; the `${name}` check runs when `job()` is called, so a name only `run(params=...)` or `modify_settings` would supply is refused. Or a `pathlib.Path` to a `.py` file, relative to the pytest rootdir, uploaded as the notebook (the `# Databricks notebook source` line is added when missing); it reads widgets itself and calls `dbutils.notebook.exit` for an output; a missing file or another suffix raises `LakeflowError`. They run on the job's compute as the injected tasks `__pytest_setup` (before every task without `depends_on`) and `__pytest_teardown` (after every leaf, `run_if` `ALL_DONE`) on every run, `only` included. Functions are shipped as source, so they must be self-contained (imports inside, no closures, no decorators, no helpers from the test module; annotations are not evaluated); a lambda, closure, decorated or REPL-defined function or other parameter raises `LakeflowError`. A returned value becomes the task's `output` as JSON. A failed setup fails the run and `repr(run)` names it first; a failed teardown only logs a warning, so assert `run.teardown.succeeded` if it matters. `teardown_at="close"` (default `"run"`) leaves the teardown task out of every run, so `run.teardown` is `None` and the assertions still see what it removes, and runs it alone when the job closes (after cancelling active runs, before the delete or keep), with `run_now(only=["__pytest_teardown"])`, the job's `params` (never a run's) and queueing on; `job.teardown_run` is that `JobRun` (not in `job.runs`; assert `job.teardown_run.teardown.succeeded`, because its own `succeeded` is false with no job task in it), `None` when no run was started, when `keep` or `--lakeflow-keep` keeps the job (`keep_failed` does not skip it, so a kept failed job is still cleaned and its teardown run is a `Kept run:` line) or when it did not finish; a failed or timed-out teardown run only logs a warning with its run page. Each run then passes `only`: `run(only=...)` gets the setup task added, and a full run lists every task but the teardown task, the disabled ones and those downstream of them, because the platform runs a disabled task that `only` names; a `key+` selection is spelt out by key, as `run_now` cannot leave a task out of it. It costs one more run start per job. `"close"` without `teardown`, or another value, raises `LakeflowError` before anything is created. `extra_dependencies` is a list of PyPI requirements, `/Workspace` or `/Volumes` wheel paths, or local wheels relative to the bundle root starting with `./` or `../` (globs and extras allowed, such as `./dist/*.whl[test]`, pointed at the copies the last deploy uploaded under `workspace.artifact_path/.internal/`, extras kept), appended to the `dependencies` of every environment taken from the template and, as `pypi` or `whl` libraries, to every notebook, Python script and Python wheel task on a cluster (nested `for_each_task` tasks included); the helper environment `__pytest_serverless` never gets them, serverless notebook tasks without `environment_key` are left unchanged and named in a `UserWarning` when the job is created, as is any enabled notebook task (not one downstream of a disabled task, the plugin's own or a stub) whose final cluster `libraries` or environment `dependencies`, after `environments` and `modify_settings`, do not hold every entry (silence it with `@pytest.mark.filterwarnings("ignore:extra_dependencies .* do not reach tasks")`; a serverless notebook task installs the `dependencies` of the environment its `environment_key` names, so move it onto one with `modify_settings`), and a local path raises `LakeflowError` before anything is created when it does not start with `./` or `../`, matches no file, has no uploaded copy (a deploy uploads only wheels a bundle job uses as a library or dependency, so another local wheel stays not found after any deploy) or is used with `sync="sync"`; a wheel with extras raises it when the copy has a Python task on a cluster, because `libraries[].whl` takes no extras. `environments` is `{environment_key: {spec_field: value}}` with `compute.Environment` fields (`environment_version`, `base_environment`, `dependencies`, ...): for a key the copy has, each field replaces the template's (so `dependencies` replaces the list, `extra_dependencies` included, and `environment_version` beats `Lakeflow(environment_version=...)`); a new key appends an environment holding only the fields passed (no `Lakeflow(environment_version=...)`, no `extra_dependencies`) that no task uses unless `modify_settings` sets a task's `environment_key`. A key starting with `__pytest_`, an override that is not a mapping, an unknown field such as `version`, both `environment_version` and `base_environment` on one spec, or more than 10 environments (helper environment included) raises `LakeflowError` before anything is created. `base_environment` takes only an absolute `/Workspace/...` or `/Volumes/...` path ending `.yaml` or `.yml`; `jobs/create` refuses a Databricks-provided id such as `workspace-base-environments/databricks_ml_v5` and does not check that the file exists. `for_each_inputs` is `{for_each_task_key: [item, ...]}`: each list replaces that top-level task's `for_each_task.inputs` on the copy as JSON (with `{{` escaped, so an item reaches the iteration as written), so a test of two items runs two iterations; an empty list runs none and the downstream tasks still run; a key that is not a task or has no `for_each_task`, a value that is not a list, is not JSON-serialisable, is over 5,000 characters as JSON, mixes objects with primitives or holds `None` or a nested list (all of which `jobs/create` refuses) raises `LakeflowError` before anything is created; objects may hold lists, objects and `None`. The for-each task is one `TaskRun`: its iterations are not in the result, and the nested task cannot be targeted. `trigger` is `{path: value}` with the path after `job.trigger.` as the reference spells it (`"type"`, `"table_update.updated_tables"`, `"file_arrival.location"`, `"time.iso_date"`; flat dotted keys, not nested dicts) and a string value: every `{{job.trigger.<path>}}` reference in the copy's settings (nested `for_each_task` tasks and parameter lists included) becomes `{{job.parameters.__pytest_trigger_<path with . as _>}}`, and that parameter is appended after the job's own with the value as its default, so every run sees it (left out of `run.parameters`; `run(params=...)` cannot set it, the `__pytest_` prefix is reserved); a list-valued reference gets exactly the string given. A path no reference uses (`trigger names 'nope', but the job has no {{job.trigger.nope}} reference`) or a value that is not a string raises `LakeflowError` before anything is created; a trigger reference left out emits a `UserWarning` (`The job still refers to [...], which trigger does not set.`). Without it, run-now resolves `{{job.trigger.type}}` to `one_time` and `{{job.trigger.time.*}}` to the time of the run, and `jobs/create` refuses `table_update` and `file_arrival` references because the copy has no trigger, so one that `trigger` does not set raises `LakeflowError` when the job is created (after `modify_settings`), naming the task or job parameter and the reference. `run.trigger_type` stays `"ONE_TIME"`; references that `modify_settings` adds are not rewritten. `task_overrides` is `{task_key: {field: value}}` with the fields `timeout_seconds` (per attempt), `max_retries`, `min_retry_interval_millis` and `retry_on_timeout`, set on the copy's task; an unknown task key (stubs, probes, setup and teardown included) or another field raises `LakeflowError` before anything is created. `disable_auto_optimization` stops serverless's own retries only, so `max_retries` still applies and each attempt is in `TaskRun.attempts`. A Run Job task keeps its deployed `job_id`, so the copy runs the deployed child job: `children="warn"` emits a `UserWarning` per such task that is not disabled (nor downstream of a disabled task, nor inside a disabled `for_each_task` loop), `children="refuse"` raises `LakeflowError` before creating anything; disable the task or its loop to skip the child. `disable` is a list of task keys to disable in the copy; they end `DISABLED` in `run.disabled_tasks`, not `run.skipped_tasks`, and so does every task downstream of them, which the platform disables too (its code does not run, so `run.succeeded` can be true while it did nothing: assert on `run.executed_tasks`); when nothing is left enabled the platform skips the run: every task is in `run.disabled_tasks` with no result state, `run.succeeded` is false and `repr(run)` says `run: Skipped because every task is disabled. ...`. `force_conditions` is `{condition_task_key: True | False}`: the copy's condition task compares constants (`true == true` or `true == false`), so every run takes that branch while the upstream tasks still run; a key that is not an enabled condition task (one downstream of a disabled task counts as disabled), or an outcome that is not a bool, raises `LakeflowError`. `task_params` is `{task_key: {name: value}}` or `{task_key: [arg, ...]}` in the shape the task type takes: a mapping is merged into notebook `base_parameters`, Python wheel `named_parameters` (clearing `parameters`) or SQL `parameters`, keeping the template's other entries such as `{{tasks.x.values.y}}`; a list replaces Python script, JAR or Python wheel `parameters` (clearing `named_parameters`) or dbt `commands`. Values pass unchanged. A mapping name that is also a job parameter (declared, or in `params`) emits a `UserWarning` ("The job value wins"), because job parameters override task parameters of the same name. An unknown task key, an injected `__pytest_` task, a task of another type (condition, pipeline, run-job, `for_each_task`, ...), a value of the wrong shape (a list for a notebook task, non-string values) or a parameter name starting with `__pytest_` raises `LakeflowError` before anything is created; check the result with `run.task(key).parameters`. `capture_task_values` is `{task_key: [value_key, ...]}`. `run_as` is `None` (strip it, run as the caller), `"keep"` (the template's), a user's email, a service principal's application id, or a `jobs.JobRunAs`. A service principal needs the Service Principal User role (Manager does not include it; admins need it too): when the client knows its account id, a missing role raises `LakeflowError` before `jobs.create`, and a `PermissionDenied` from `jobs.create` becomes a `LakeflowError` naming you, the principal and the role, with the original as `__cause__`.
- `lakeflow.task("job_key.task_key", params=None, upstream_task_values=None, capture_task_values=None, run_as=None, *, task_params=None, upstream_from=None, children="warn", setup=None, teardown=None, teardown_at="run", extra_dependencies=None, environments=None, task_overrides=None, pipelines="deployed", schema=None, for_each_inputs=None, trigger=None) -> EphemeralJob`. `children`, `setup`, `teardown`, `teardown_at`, `extra_dependencies`, `environments`, `task_overrides`, `pipelines`, `schema` and `trigger` as for `job()`, though `task_overrides` may name only the task under test; `for_each_inputs` is a list for the task under test, as for `job()`, and raises `LakeflowError` when it has no `for_each_task`; setup runs before the stubs. `task_params` as for `job()`, but it may name only the task under test, and is applied before the stubs, so a `{{tasks.x.values.y}}` it adds needs `x` in `upstream_task_values`. `upstream_task_values` is `{upstream_task_key: {value_key: value}}` or `{upstream_task_key: Stub(values={...}, outputs={...})}`: a stub is a notebook task with no SQL, alert or other output, so each `{{tasks.<key>.output.<path>}}` reference in the target's settings is replaced by `outputs[path]` (the path after `output.` exactly as spelt, such as `first_row.n`, `first_row`, `rows`, `alert_state`; a string verbatim, anything else as compact JSON); a reference whose path the stub does not give (a plain mapping gives none), an output reference to a notebook task of the copy that is not a stub (the Jobs API refuses it at create with "Unsupported task type for the 'output' namespace."), an output containing `{{` or one that is not JSON-serialisable raises `LakeflowError` before anything is created. The platform spells `rows` and `first_row` as compact JSON with every value a string and `NULL` as `""`, such as `[{"n":"1","m":""}]`, so stub them the same way. A `{{tasks.<key>.values...}}` reference in the target's settings to a task that is not stubbed raises `LakeflowError` (`refers to task values of [...]`) before anything is created, and so does any other `{{tasks.<key>.` reference to one, such as `result_state`, because `task()` drops the task from the job and `jobs/create` refuses a reference to a task the job does not have. `capture_task_values` is a list. `upstream_from` is a `JobRun` of the same job that captured every upstream task's values (`capture_task_values={upstream_task_key: [...]}` on `job()`); it stubs each task the target depends on with them, and an `upstream_task_values` entry replaces the values for that task.
- `lakeflow.schema(catalog=None)`: context manager yielding a temporary `catalog.schema` name. Needs `catalog`.
- `lakeflow.attach(run_id) -> JobRun`: rebuilds the `JobRun` of a finished run of a kept job (the job run id at the end of the `Kept run:` URL) from the job's `pytest_job_key` tag and its stub and probe tasks, without running, deploying, cancelling or deleting anything. Inside a test only. Raises `LakeflowError` for a missing run, a task run, a run that has not finished, a deleted job or a job the plugin did not create.
- `lakeflow.pipeline(key, schema, *, configuration=None, name=None) -> EphemeralPipeline`: a throwaway copy of the bundle pipeline `key`, made from the deployed spec (`ws.pipelines.get(id).spec`, so it runs the code the last deploy uploaded), publishing to `schema` (a full `catalog.schema` name, in the deployed pipeline's publishing mode: `target` if it uses that, else `schema`), with `development=True`, `allow_duplicate_names=True`, name `[pytest] <name or node id>` cut to 255 characters (the platform's limit), the job tags (`pytest`, `pytest_run_id`, `pytest_nodeid`, `pytest_expires`, attribution) merged over the deployed tags (25 at most), `configuration` merged over the deployed configuration, `Lakeflow(budget_policy_id=...)` when set, and without `deployment`, `continuous`, `trigger`, `notifications` or `event_log`; it runs as you. Only tables the pipeline's code names without a schema go to `schema`. Use it in `with lakeflow.schema() as s, lakeflow.pipeline("key", schema=s) as p:` so the copy is deleted (with `cascade=True` and `force=True`, so its tables go too) before the schema is dropped. Needs `sync="deploy"` (else `LakeflowBundleError`); an unknown key raises `KeyError` listing the bundle's pipelines; a pipeline that is not deployed or no longer exists, `LakeflowBundleError`; a `schema` without a catalog or a Hive metastore pipeline (no `catalog`), `LakeflowError`.
- `EphemeralPipeline`: `pipeline_key`, `source_id` (the deployed pipeline's id), `schema`, `create_kwargs`, `pipeline_id` (once created), `url` (`<host>/pipelines/<id>`), `updates`, `create()`, `close(failed=False)`, and `run(*, full_refresh=None, full_refresh_selection=None, refresh_selection=None, timeout=None) -> PipelineUpdate`, which creates the copy if needed, starts an update and polls it until `COMPLETED`, `FAILED` or `CANCELED`, logging each state change (`pipeline <key>: RUNNING -> COMPLETED`) into the `lakeflow` report section; a failed update is returned (`update.state == "FAILED"`, read `update.events(level="ERROR")`), not raised; a timeout (default `Lakeflow`'s `timeout`) stops the update and raises `LakeflowTimeout` (`Update <id> of pipeline '<key>' did not finish within <timeout> and was stopped: <url>`); a selection given as a string raises `LakeflowError`. Created on entering `with` or by the first `run()`, deleted on leaving the block or at the end of the test, unless the keep rules keep it (`Keeping pipeline <id> from <key>: <url>`, listed as `lakeflow: N pipelines kept` in the terminal summary). The user properties `lakeflow_pipeline_url` and `lakeflow_pipeline_id` name it. An update still running at session end is stopped.
- `lakeflow.ws`: the `WorkspaceClient`. `lakeflow.template(key)`: a fresh `JobSettings` copy. `lakeflow.check(key) -> list[str]`: lints the template without creating or running anything, one message per problem, each starting with `Task '<key>':` in task order: an undeclared `{{job.parameters.<name>}}`, a `{{tasks.<key>.values.<name>}}` whose task is not upstream (a task nested in a `for_each_task` shares its upstream), a `depends_on` task that is not in the job, and `max_retries`, `min_retry_interval_millis` or `retry_on_timeout` set on a `for_each_task` (0 and false are not reported); raises `KeyError` and `LakeflowBundleError` as `template` does; works in a session-scoped fixture. Use `problems = lakeflow.check(key); assert not problems, "\n".join(problems)`.
- `EphemeralJob.run(params=None, only=None, timeout=None, *, stop_after=None, performance_target=None, queue=None, full_refresh=None, full_refresh_selection=None, refresh_selection=None, refresh_flow_selection=None, reset_checkpoint_selection=None, replay=None, stream=None) -> JobRun`. `stream` (keyword-only) prints `lakeflow: Started run ...`, each task state change and `lakeflow: Run ... finished ...` to the terminal while waiting, past output capture; `None` follows `--lakeflow-live`, `False` keeps the run quiet under it; an xdist worker prints nothing and only logs. `only` takes task keys with `+key`, `key+`, `+key+`; naming a task that is disabled in the copy (by `disable`, the bundle or `modify_settings`) or downstream of a disabled task, with or without `+`, raises `LakeflowError` (`only names [...]`) before the run starts, because the platform runs a disabled task that `only` names, and with `key+` the tasks downstream of it, while a `+` that only reaches a disabled task leaves it out; a selected task that refers to `{{tasks.<key>.values...}}` of a task that is neither selected nor a stub that runs raises `LakeflowError` (`refers to task values of [...]`) before the run starts, so use `only=["+transform"]` or stub the task; so does one that refers to `{{tasks.<key>.output...}}` of such a task (`refers to the output of [...]`; the platform would fail the run with INVALID_RUN_CONFIGURATION "Cannot access output from task '<key>' because the task was skipped."), so select it or stub it with `Stub(outputs=...)`; other references such as `{{tasks.<key>.result_state}}` resolve against the left-out task's `DISABLED` run (`disabled`) and are not checked. `replay` (keyword-only) is a `JobRun` of the same job that captured the values (`capture_task_values` on `job()`): each task a selected task depends on and `only` leaves out becomes a stub with that run's values; it needs `only` and must go to the first run of a new `lakeflow.job(...)` (a created job raises `LakeflowError`). `performance_target` (`"PERFORMANCE_OPTIMIZED"` or `"STANDARD"`) and `queue` (a bool) are keyword-only and apply to that run only. `full_refresh` (a bool), `full_refresh_selection` and `refresh_selection` (lists of tables), `refresh_flow_selection` (flows) and `reset_checkpoint_selection` (streaming flows whose checkpoints are reset), the four lists needing databricks-sdk 0.110.0 or later, are keyword-only, go to the run's pipeline tasks as `pipeline_params`, and raise `LakeflowError` on a job with no pipeline task; the pipeline is the deployed one unless the job was made with `pipelines="copy"`. Also `job_id`, `url`, `runs`. On timeout `LakeflowTimeout` cancels the run and its message ends with `Tasks when cancelled: extract SUCCESS, transform RUNNING, ...`. `stop_after` (a `timedelta`, keyword-only) is for a job that never ends on its own, such as a streaming job: that long after the run started the plugin cancels it once, polls until it has ended and returns a `JobRun` with `cancelled` true (and `failed` true; its cancelled tasks have `ran` false and no `output`, `logs` or `error`), appended to `job.runs` and passed to `run_finished`; `stop_after` longer than the timeout raises `LakeflowError` before the run starts, and a run still going at the timeout raises `LakeflowTimeout` without a second cancel, so give a `timeout` comfortably longer than `stop_after` (equal ones always end in `LakeflowTimeout`).
- `EphemeralJob.start(params=None, only=None, *, timeout=None, performance_target=None, queue=None, full_refresh=None, full_refresh_selection=None, refresh_selection=None, refresh_flow_selection=None, reset_checkpoint_selection=None) -> RunHandle` starts a run as `run()` does without waiting; `run(params, only, timeout, stop_after=s)` is `start(params, only, timeout=timeout).wait(stop_after=s)`. `start(timeout=...)` lengthens the job's `timeout_seconds` before the run starts, as `run(timeout=...)` does, and becomes the default timeout of `wait()`. `RunHandle` has `job`, `run_id`, `url` (known once `start()` returns), `wait(timeout=None, *, stop_after=None) -> JobRun` (appends to `job.runs`; a `timeout` longer than the job's `timeout_seconds` raises `LakeflowError`, so pass long timeouts to `start()` or `run()`; `stop_after` counts from `start()` and, longer than the wait's timeout, raises `LakeflowError` and leaves the run going; a second call returns the same `JobRun` and does not call `run_finished` again; after the job closed it raises `LakeflowError`) and `cancel()`. A copy allows one run at a time, so to run jobs side by side start runs of separate `lakeflow.job(...)` copies, then wait for each. A run never waited for is cancelled when its job closes or at session end.
- `EphemeralJob.debug_notebook(task_key, run=None) -> DebugNotebook` writes a notebook to `<helpers_path>/debug/<job_key>__<task_key>__<run_id>` (replacing one of the same run) that sets the task's resolved parameters (`run.task(task_key).parameters`, the plugin's own keys included) as `dbutils.widgets.text` widgets and then `%run`s the task's notebook path from the copy's settings; `run` defaults to `job.runs[-1]`. `DebugNotebook` has `task_key`, `run_id`, `path` and `url` (`<host>/#notebook/<object id>`, also `str()`); the URL is added to the test's user properties as `lakeflow_debug_notebook`. It raises `LakeflowError` for an unknown task, a task that is not a notebook task (stubs included), a notebook with `source: GIT`, a job with no run, or a task that did not run or has no resolved parameters, and `KeyError` (from `run.task`) for a task not in the run. A value over 2048 bytes is kept whole in a `parameters` dict and truncated in its widget, and a first cell of comments names those parameters. It replays parameters only: `dbutils.jobs.taskValues.get()` without `debugValue=` raises `TypeError` in it.
- `JobRun`: `succeeded`, `failed`, `raise_for_failure()` (returns the run, or raises `LakeflowRunFailed` whose `run` is the run), `tasks`, `task(key)` (a `KeyError` says `Skipped by only` or `Disabled in the job`), `executed_tasks` (sorted keys of `tasks` that ran), `branch_taken(key)` (a condition task's `condition_outcome`; `LakeflowError` for any other task), `skipped_tasks` (left out by `only`, nothing else), `disabled_tasks` (disabled in the bundle or with `disable`, and the tasks downstream of them), `injected_tasks`, `setup` and `teardown` (the `TaskRun` of the setup or teardown task, or `None`; `teardown` is also `None` when `teardown_at="close"` left it out of the run), `result_state`, `termination_code`, `termination_message`, `duration`, `run_id`, `run_url`, `timed_out` (the run or any task ended `TIMEDOUT`), `cancelled` (the run ended `CANCELED`, as after `stop_after` or `handle.cancel()`; also `failed`), `parameters` (job parameters by name, the run's value or the default, without the plugin's own), `timing` (a `Timing` with `queue`, `setup`, `execution`, `cleanup` as `timedelta` and `total`; zero when not reported, and zero on the parent of a multi-task run, so read it on tasks), `effective_performance_target` (`"STANDARD"`, `"PERFORMANCE_OPTIMIZED"` or `None`), `trigger_type` (what started the run as the Jobs API reports it: `"ONE_TIME"` for a copy, whatever `trigger=` simulates; `None` when not reported), `job_key` and `job_id` (the bundle key and the ephemeral job's id; for a `child_run`, the child job's). `repr(run)` adds `params={...}` when the run failed.
- `TaskRun`: `succeeded`, `ran` (false for `EXCLUDED`, `UPSTREAM_FAILED`, `UPSTREAM_CANCELED`, `DISABLED`, `CANCELED` and no result state), `excluded` (`EXCLUDED` by `run_if` or if/else), `upstream_failed`, `disabled`, `cancelled` (each an exact match of `UPSTREAM_FAILED`, `DISABLED`, `CANCELED`), `condition_outcome` (`True`, `False`, or `None` for a task that is not an if/else condition task), `result_state`, `termination_code`, `termination_message`, `output` (falls back to a clean room notebook task's output), `output_json`, `output_truncated`, `sql_output`, `alert_output`, `dbt_output`, `run_job_output`, `dashboard_output`, `clean_rooms_notebook_output` (the SDK objects from `runs/get-output`, each `None` for other task types; `sql_output` holds no query rows), `sql_result` (a SQL file task's rows as a `SqlResult`, read from the raw `runs/get-output` field `sql_output.file_output` that databricks-sdk does not model: `columns`, `types`, `rows` (dicts by column name, values as strings, NULL as `None`), `first_row` (raises `LakeflowError` "returned no rows" when empty), `truncated` (cut at 1,000 rows), `warehouse_id`, `query_text` (`:name` markers kept); `None` for saved query, alert and dashboard tasks, a task that did not run, or an unreadable output), `pipeline_update` (a pipeline task's update as a `PipelineUpdate`, also what `EphemeralPipeline.run()` returns: `pipeline_id`, `update_id`, `state` (`"COMPLETED"`, `"FAILED"`, ...), `cause` (`"JOB_TASK"`, or `"API_CALL"` from `EphemeralPipeline.run()`), `full_refresh`, `events(level=None)` (that update's `pipelines.PipelineEvent`s, newest first, e.g. `events(level="ERROR") == []`); found by `pipelines.list_updates` as the update created between the task's start and end, a `JOB_TASK` one first; `None` for other tasks, a task that did not run, or no match, which logs a warning naming the task and pipeline), `alert_state` (`"TRIGGERED"`, `"OK"`, `"ERROR"`, `"UNKNOWN"` or `None`; an alert task succeeds whether or not it triggered, so assert on this; `"ERROR"` comes with a failed task, when the alert's query failed, whose `error` is then the task's termination message with `type` `None`), `child_run_id` (the run id a run-job task triggered, from `run_job_output.run_id`; `None` for other tasks), `child_run` (that run as a `JobRun`: `job_id` is the child job's, `job_key` its bundle key when the bundle deployed it, else `str(job_id)`; nested for a child's own run-job tasks; a task disabled in the child job is in its `disabled_tasks`; each of `attempts` has its own; `None` for other tasks, when the task did not run or the run could not be read), `logs`, `log_lines`, `logs_truncated`, `notebook` (a `NotebookView` read with `jobs.export_run` for the notebook tasks `notebook_export` selects, else `None`: `cells`, each a `NotebookCell` with `index`, `code`, `output` (text, HTML and ANSI removed), `output_html`, `error` (`"Name: message"` or `None`) and `stdout`; `stdout` (what every cell wrote to standard output in order, what `print()` produced; stderr, displayed results and the `dbutils.notebook.exit()` value are only in the cells' `output`); `failed_cell` (the first cell that raised, or `None`); `html` (the export, unchanged); `save(path)`; an unreadable export gives empty `cells` and a `UserWarning` naming the `__DATABRICKS_NOTEBOOK_MODEL` marker, once per test), `error` (`type`, `message`, `trace`, `root_cause`, `code`; `None` for a pipeline task that succeeded, although the Jobs API reports one), `raised(ExcType)`, `task_values`, `missing_task_values`, `duration`, `timing`, `effective_performance_target`, `attempt`, `attempts` (one `TaskRun` per attempt in order, the last equal to the task apart from `attempts`; only the last has a `notebook`), `timed_out` (ended `TIMEDOUT`), `run_url`, `parameters` (resolved task parameters: a dict for notebook, SQL (a SQL file task's also holds every job parameter), run-job and named wheel parameters (also every job parameter), a list for positional wheel, Python script, JAR, spark-submit and dbt tasks, else `None`, or when the task did not run or its task run could not be read; printed by `repr()` when the task has an error).
- Flags: `--lakeflow-live` (prints each run's start, task state changes and end to the terminal as `lakeflow: <line>` while a run waits, without `--log-cli-level` or `-s`; not under xdist, where the lines are only logged), `--lakeflow-debug-notebook` (when a test fails, call `debug_notebook` as its job closes for each task of the job's last run that ran, did not succeed and is a notebook task; errors only log a warning; the URLs go to the report section, JUnit XML and the terminal summary as `lakeflow: N debug notebooks written`, then one line each, `<url> (<nodeid>, task '<key>')`, plus `; widgets cut at 2048 bytes: '<name>'` when a value did not fit its widget, so a notebook whose job a fixture's finaliser closed, which lands on the teardown report shown only with `-rA`, is still listed), `--lakeflow-keep`, `--lakeflow-keep-failed`, `--no-lakeflow-keep-failed`, `--lakeflow-keep-ttl=48h` (tags every job and pipeline copy `pytest_expires`, an ISO 8601 UTC time 48 hours ahead; `h` or `d` only; the sweep keeps it until then, whatever its age), `--lakeflow-sweep` (deletes your `pytest`-tagged jobs and `[pytest] ` pipeline copies, with their tables, of other runs older than `sweep_hours`, by creation time for jobs and last change for pipelines), `--lakeflow-destroy`, `--lakeflow-report-dir=DIR` (a `report.json` per test with each run it waited for, plus each run the plugin cancelled at a timeout or when its job closed, polled for at most 60 seconds until it ended and listed as `CANCELED` without reaching `job.runs` or `run_finished`; a run cancelled when a module- or session-scoped fixture closes its job is listed by the test being torn down; at session start the directories an earlier session wrote are deleted, nothing else in `DIR`). With `--lakeflow-sweep` only: `--lakeflow-sweep-scope=mine|all` (all: any creator), `--lakeflow-sweep-schemas=<catalog>` (old `pytest_<run id>_<8 hex>` schemas of other runs), `--lakeflow-sweep-notebooks` (old `setup_<12 hex>` and `teardown_<12 hex>` notebooks in the helpers folder, by upload time alone, so even those of jobs a `pytest_expires` tag still protects; never `set_values` or `get_values`), `--lakeflow-sweep-branch=<branch>` (jobs and pipeline copies tagged `pytest_git_branch=<branch>` only; a usage error with the schema or notebook flag), `--lakeflow-sweep-dry-run` (deletes nothing; the terminal summary lists what it would delete), `--lakeflow-sweep-report=<path>` (JSON with `version`, `dry_run`, `jobs`, `pipelines`, `schemas`, `notebooks`, `errors`). A sweep that fails outright, such as on an unwritable report path, emits one `UserWarning` (`Lakeflow sweep failed: ...`) on the process that swept and fails no test. There are no ini options and no other fixtures. `--lakeflow-report-dir` (relative to the invocation directory) writes, for each test that waited for a run, `DIR/<sanitised nodeid>-<8 hex>/report.json` with `nodeid`, `outcome` per phase, `debug_notebooks` (`task_key`, `run_id`, `path`, `url` of each debug notebook the test wrote; a test that waited for no run but wrote one still gets a report) and `runs` (each `serialise(run)` plus `job_url`, `params`, `settings`), and the side files `<run_id>/<task_key>.log` (non-empty `logs`) and `<run_id>/<task_key>.html` (exported `notebook`); a serialise or write error only logs a warning and never ends the session.
- `pytest_databricks_lakeflow.results.serialise(run) -> dict`: the `JobRun` as JSON-serialisable data with every field, `duration_seconds` instead of `duration`, `timing` in `*_seconds`, `error` as a dict or `None`, `missing_task_value_reasons`, `succeeded`, and `logs_file` and `notebook_file` (paths relative to the test's report directory, or `None`) instead of `logs` and `notebook`; an earlier attempt of a retried task gets `.attempt-<n>` before the suffix.

Do not invent arguments, fixtures, markers or flags beyond these. Check the signature in the API reference when unsure.

## Patterns

Job test:

```python
from pytest_databricks_lakeflow import Lakeflow


def test_job_succeeds(lakeflow: Lakeflow) -> None:
    with lakeflow.job("my_example_job", params={"param1": "hello", "param2": "world"}) as job:
        run = job.run()
        assert run.succeeded, run  # or: run.raise_for_failure()
        assert run.task("transform").output == "hello world"
```

Expected failure:

```python
def test_rejects_forbidden_input(lakeflow: Lakeflow) -> None:
    with lakeflow.job("my_example_job", params={"param1": "forbidden", "param2": "world"}) as job:
        run = job.run()
        assert run.failed
        assert run.task("transform").raised(PermissionError)
        assert run.task("load").result_state == "UPSTREAM_FAILED"
```

Single task with stubbed upstream values and captured values:

```python
def test_transform(lakeflow: Lakeflow) -> None:
    with lakeflow.task(
        "my_example_job.transform",
        params={"param1": "hello", "param2": "world"},
        upstream_task_values={"extract": {"row_count": 42, "source_path": "/Volumes/x/y/z"}},
        capture_task_values=["rows_written"],
    ) as task:
        run = task.run()
        assert run.succeeded, run
        assert run.task("transform").task_values["rows_written"] == 42
```

Replay one task with the upstream values a full run captured:

```python
def test_replay_transform(lakeflow: Lakeflow) -> None:
    first = lakeflow.job("my_example_job", capture_task_values={"extract": ["row_count", "source_path"]}).run()
    with lakeflow.task("my_example_job.transform", upstream_from=first) as task:
        run = task.run()
        assert run.succeeded, run
```

Run the downstream half of a job with a stubbed or replayed upstream task:

```python
def test_downstream_half(lakeflow: Lakeflow) -> None:
    stubbed = {"extract": {"row_count": 7, "source_path": "/Volumes/x/y/z"}}
    run = lakeflow.job("my_example_job", upstream_task_values=stubbed).run(only=["transform+"])
    assert run.succeeded, run
    first = lakeflow.job("my_example_job", capture_task_values={"extract": ["row_count", "source_path"]}).run()
    again = lakeflow.job("my_example_job").run(only=["transform+"], replay=first)
    assert again.succeeded, again
```

Tables in a temporary schema:

```python
def test_writes_rows(lakeflow: Lakeflow) -> None:
    with lakeflow.schema() as schema, lakeflow.job("my_example_job", params={"schema": schema}) as job:
        assert job.run().succeeded
        assert lakeflow.ws.tables.exists(f"{schema}.example_rows").table_exists
```

A copy of a bundle pipeline, on its own or under its job, publishing to a temporary schema:

```python
def test_pipeline_copy(lakeflow: Lakeflow) -> None:
    with lakeflow.schema() as schema, lakeflow.pipeline("my_pipeline", schema=schema) as pipeline:
        update = pipeline.run(full_refresh=True)
        assert update.state == "COMPLETED", update.events(level="ERROR")
    with lakeflow.schema() as schema, lakeflow.job("my_pipeline_job", pipelines="copy", schema=schema) as job:
        assert job.run(full_refresh=True).succeeded
```

Seed data before the job runs, on the job's own compute:

```python
def seed_orders(spark, params):
    spark.sql(f"CREATE OR REPLACE TABLE {params['schema']}.seed_orders AS SELECT 1 AS id, 'a' AS sku")


def test_reads_seeded_orders(lakeflow: Lakeflow) -> None:
    with lakeflow.schema() as schema:
        with lakeflow.job("my_example_job", params={"schema": schema}, setup=seed_orders) as job:
            run = job.run()
            assert run.succeeded, run
            assert run.setup.succeeded
```

Use `@pytest.mark.parametrize` for input variations and `job.run(only=["+task"])` for a subset. Call `run()` twice on one job to compare runs.

## Rules

- Assert with plain `assert`. Put the run in the message: `assert run.succeeded, run`, or call `run.raise_for_failure()`.
- Use `run.succeeded`, never `run.result_state`, as the verdict.
- Pass only parameters the job declares, or the plugin raises `LakeflowError`. Names starting with `__pytest_` are reserved.
- `logs` exist only for Python script, wheel and JAR tasks. Notebook tasks have `output` (the `dbutils.notebook.exit()` value) and, when they ran and did not succeed, `notebook.stdout` with what they printed; pass `Lakeflow(notebook_export="always")` to assert on what a passing notebook printed.
- Stub values must be JSON-serialisable and under 49,152 characters each. Stub every upstream task whose values the task reads.
- Do not run the deployed jobs, call `jobs.run_now` yourself, or delete jobs in tests. The plugin owns the lifecycle.
- Keep tests that need a workspace separate from fast tests: they get the `lakeflow` marker automatically, so `pytest -m "not lakeflow"` skips them.

## Running

```bash
pytest tests/ --lakeflow-live               # deploys the target, runs each test, prints each task's state changes
pytest tests/ -n 4                          # parallel, needs the xdist extra
pytest tests/ --lakeflow-keep               # keep jobs and schemas to inspect
pytest tests/ --lakeflow-sweep              # delete leftovers from earlier runs first
pytest tests/ --lakeflow-report-dir=build/lakeflow  # report.json, logs and notebooks per test
pytest tests/ --lakeflow-sweep --lakeflow-sweep-dry-run   # list what the sweep would delete
```

While a run is in flight, each task's change of state is logged at INFO (shown with `--log-cli-level=INFO`) and, with `--lakeflow-live`, printed as `lakeflow: <line>`, such as `transform: RUNNING -> FAILED in 0:00:42 ValueError: no rows`, and the same lines follow the job and run URLs in the test's `lakeflow` report section, shown for failures and with `-rA`. A failed run also reports its job parameters and its failing tasks' resolved parameters, as `lakeflow_params` and `lakeflow_task_params` in that section and in JUnit XML, and as `params:` lines in the `raise_for_failure()` message. Kept jobs and schemas are listed in a `lakeflow` block at the end of the run. Every ephemeral job is tagged `pytest`, `pytest_run_id` and `pytest_nodeid`, plus `pytest_ci_url`, `pytest_user`, `pytest_git_sha` and `pytest_git_branch` when they can be resolved.

Needs the Databricks CLI v1.7.0 or later on `PATH`, credentials for the CLI and the SDK, and serverless jobs (or `helpers_compute="<job_cluster_key>"`).
